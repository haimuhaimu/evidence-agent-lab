# Security Policy

## Reporting a vulnerability

After this repository is published, report vulnerabilities through GitHub private vulnerability reporting. Include the affected version, a minimal reproduction, impact, and any suggested mitigation.

Do not open a public issue for credentials, tokens, personal data, or another sensitive finding. Do not include secrets or real records in any report; use redacted steps and synthetic examples.

Before publication, keep the report private and share it only with the repository owner through an already established trusted channel.

## Supported scope

Security reports should concern this local demonstration and its dependencies. The project performs no production action, sends no external notification, and stores review entries only in the current browser.
